# Charting (course creation)

Charting writes graph content into the learner's own Notebook (the Personal
scope delta); no discrete Patch exists until publication reifies a View.
The authoring ladder is per-node and lazy: criterion at inventory, items at
first probe, material at first teach. Threshold-flagged nodes may
front-load items.

Reads: `preferences()`, `coverage(scope)`, `mission(scope?)`; hub search
and personal recall search.

## Steps

1. Mission interview.

@../snippets/mission-interview.md

2. Coverage check. `(query)` `coverage` over the User graph for the
   mission's terms; hub search when the Hub is worth searching. `(model)`
   If existing graph regions or an adoptable Patch cover part of the scope,
   propose targeting or adopting instead of charting. `(learner)` Confirms.
   Done when the novel scope is stated.

3. Node inventory, edges, and source grounding, in that order per slice:

@../snippets/graph-authoring.md

4. Handoff. `(model)` Hand the Mission and every Observation made during
   the conversation to a calibration session over the new slice. The first
   lesson is always a separate session after calibration has mapped the
   learner's position. Charting sessions do not run lessons.

## Publication

Publication is the only Patch-surfacing flow. `(query)` Coverage checks
over the View being published: unreachable nodes, nodes without items or
materials, edges without justification. These checks gate sharing, not
personal use; a personal chart runs on partial content indefinitely.
`(model)` Presents the report. `(author)` Resolves each line and confirms.
Reify the View into a fresh Patch and publish an immutable revision.

## Emits

The Mission Observation, preference and other experience Observations from
the conversation, and the graph delta in the Notebook. Publication emits a
reified Patch revision. Charting produces no learning evidence: competence
the author displays is recorded, if at all, by the calibration session the
handoff opens.
