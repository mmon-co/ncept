# Realignment

1. Read `warnings(scope?)`, `mission(scope?)`, `trail(node)`, and `items(node)`.
   Warnings report item outcomes, edge contradictions, instability, mistake
   clusters, unused content, homeless Records and self-report contradictions.
   None is proof of a content defect; inspect the cited task/response first.
2. Wrong task/outcome recording → explain the local correction rather than
   changing content. Defective edge or capability grain → graph authoring.
   Defective task or exposition → quiz authoring or material work.
   Goal/View drift → discuss it; there is no View-retargeting procedure here.
3. With the learner's edit-session authority, propose only the supported host
   graph/material change and wait for Confirmation before applying it. Explain
   which retained UUIDs still assert the same capability and which are removed.
4. The host delivers the complete log and both exact graphs to the theory's
   update path; declared successors give provisional homes only. The background
   sweep uses `refine_records` to home pending tasks by content. Read `trail`
   and `warnings` under the new revision, preserving its overlay on every read.
   Homeless Records remain visible, not discarded or silently declared learned.
5. Recount the change and its effect on cited Records. Do not promise changes
   to other Profiles or publication workflows.
