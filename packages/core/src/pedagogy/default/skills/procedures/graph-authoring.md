Write graph content into the Notebook only through the host's mounted Confirmation affordance in a learner-approved exclusive edit session. A Personal scope is already a Patch; publication is not part of this procedure.

1. Inventory a small useful slice. Each Node asserts one capability, with `display:label` and pedagogy:criterion in a Metadata set attached to its UUID. pedagogy:knowledge-type, pedagogy:threshold and pedagogy:guidance are optional authoring notes. Materials (Problems, cards, Documents) are lazy, not prerequisites for charting.
2. Test each Edge: can the dependent be demonstrated without the prerequisite? Only "no" warrants necessity; write the reason in the Edge's pedagogy:because. Teaching order and presentation are not Edges. A dependent with more than a few prerequisites is a grain defect or a list of helpful context: split the capability or drop the Edges, never keep them as emphasis. The host rejects cycles and dangling endpoints before approval; read its proposal-time report instead of computing reachability yourself.
3. Ground the slice in the learner's actual target and available trusted sources. Explain uncertainty, rather than fabricate corroboration or a Hub result.
4. Submit the graph diff, or a Mission carrying the diff, through the host's mounted proposal tool. Wait for acceptance and successful application before referring to the Nodes as existing. A failed Confirmation is not a saved edit.

## Structure guidelines

- Different task presentations → one capability Node, not separate identities.
- Unclear grain → ask whether the parts have different necessary Edges.
- Same capability in a revision → retain UUID; a new UUID is a new identity.
- Removed identities → successors are provisional hints, not evidence. The theory's update and background content pass own record homes, not graph Edges.
- Unavailable edit affordance → discuss the proposed content without claiming that a Node, View, item or material has been saved.
