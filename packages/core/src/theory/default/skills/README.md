# Default theory Skill catalog

Markdown is the authoring source for six Agent Skills and four Session-mode procedures, plus their shared procedures. `base.md` holds the always-loaded tutor instruction. Each non-mode `<name>/SKILL.md` declares its name, description, facet (`position`, `chart`, `advance`) and permitted entries (`learner`, `model`, `system`). `charting/SKILL.md`, `authoring/SKILL.md`, `lesson/SKILL.md` and `scene/SKILL.md` supply their mode procedures automatically; they are not Skills in the loadable catalog. `@procedures/<name>.md` includes are inlined into the delivered body.

`bun scripts/default-implementation-digest.ts` embeds the Markdown in `sources.ts` and emits the executable module, typed declaration and identity from the private typed assembly. The public default Theory executes that generated module, including its Skill strings, not raw files or independently imported source. `--check` rebuilds exact checked-out inputs and compares all four outputs; `--staged` uses the frozen index and its exact dependency resolution without changing working files. `bun run build:skills` and `bun scripts/build-skills.ts --check` remain embedding-only commands. Pre-commit and final-tree rebase/merge regeneration own the same four derived files. The app-help Skill carries an adopted official Document index for reference and a separate, use/told-filtered recommendation list at each chat hook; that request-time context is not part of the static Skill release.

`../skills.ts` returns catalog values. Entries without model permission are learner-started by their slash command and carry `disable-model-invocation: true` in bundles. System-only entries are absent from the tutor index; the host must omit them from model-mounted directories. The `facet` and `entry` facts also accompany each Skill in `chat.open` and `chat.turn`, while each Session mode receives only its declared catalog.

The default theory mounts `theory` instruments and Lesson's `evaluation` envelope; their `run` methods are Programs. The host homes approved Chart draft claims, and its internal closing/event/sweep Programs own record refinement; these are not interactive aliases. Scene and the system-only evaluator sweep retain their isolated Program contracts. The host supplies effective evidence and owns persistence/execution. Evaluation writes observations, never learner labels. Claims are homed by content, not Edges. Memory compaction belongs to the closing-span Program and never creates demonstration evidence. Host graph, Confirmation, Material, code and review actions remain host tools, conditional on what is actually mounted.
