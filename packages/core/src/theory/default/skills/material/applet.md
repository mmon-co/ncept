# applet

Kind: `applet`: HTML source plus metadata, added with `node` or `about`.

**Design.** Keep the applet's state private and persisted, exposing a `summary` through a declared query, and read that. Declare the commands the interaction needs and the ones learners will ask for beside them (reset; clear move history while keeping the position), saying what each changes and keeps. Change position or help live through commands: editing the source and opening it again makes a new copy with separate state, so say so and restore the position through a command. A "comment on moves" toggle changes only whether a move wakes you; every move is still posted. When woken, read `summary` first, since a post describes a past event. Stop waking as help fades.

**Source.** Import `@concept/applet` from a module script; use `session.judge({criteria, state})` with tutor-written criteria in the source for in-play feedback, whose per-criterion probabilities are not evidence. Await `init()` before using `session`; it resolves `{ state, session, … }`: restore from its `state` field and persist with `state(value)`. After each move, `await state(nextState)`, then `session?.post(move, { wake })`; wakes share a 6-per-minute bucket and a rate-limited wake is dropped. Register `onCommand(async ({id, name, input}) => { /* apply, persist, render; return JSON */ })`; a command may be delivered again with the same `id`, so make it safe to replay. For a Node with an applet `pedagogy:completion` binding, `emit({kind: 'completion', node, state: 'complete' | 'incomplete', validUntil?})` reports completion, which changes acquisition, not recall scheduling. Use fluid width for the 420 px Materials pane, and give every interactive element a semantic role and accessible name.

**Metadata,** for example: `{"abi":"applet:1","libraries":{"@concept/applet":"1"},"queries":{"summary":"$.summary"},"commands":{"setPosition":{"inputSchema":{"type":"object","properties":{"fen":{"type":"string"}},"required":["fen"],"additionalProperties":false}}}}`. Every command declares its input schema.

**Running.** Opening mounts the applet and pins its revision. Find its commands with `read {resource:'applet', input:{surface, selection:{command}}}` and queue one with `material {kind:'applet', op:'command', command, input:{surface, arguments}}`; its result arrives on a later turn.
