# applet

Kind: `applet`: HTML source plus metadata, added with `node` or `about`.

**Design.** Keep the applet's state private and persisted, exposing a `summary` through a declared query, and read that. Declare the commands the interaction needs and the ones learners will ask for beside them (reset; clear move history while keeping the position), saying what each changes and keeps. Change position or help live through commands: editing the source and opening it again makes a new copy with separate state, so say so and restore the position through a command. State is the applet's memory, read through queries; a post is a learner action you receive on your next turn; a wake asks for that turn now. A help toggle belongs on the wake, since an unposted move never reaches you. When woken, read `summary` first, since a post describes a past event. Stop waking as help fades.

**Source.** Import `@concept/applet` from a module script; use `session.judge({criteria, state})` with tutor-written criteria in the source for in-play feedback, whose per-criterion probabilities are not evidence. Await `init()` before using `session`; it resolves `{ state, session, … }`: restore its `state` once at initialization; persist with `state(value)` while keeping inputs mounted and in-progress text/focus intact when saves finish. `await state(next)` before `session?.post(action, { wake })`, so a wake's inspection sees it. Posts allow 60 a minute per applet, so batch faster actions into one post; wakes share a 6-per-minute bucket per Session, and a rate-limited wake is dropped while its post stands. Register `onCommand(async ({id, name, input}) => { /* apply, persist, render; return JSON */ })`; a command may be delivered again with the same `id`, so make it safe to replay. For a Node with an applet `pedagogy:completion` binding, `emit({kind: 'completion', node, state: 'complete' | 'incomplete', validUntil?})` reports completion, which changes acquisition, not recall scheduling. Use fluid width for the 420 px Materials pane, and give every interactive element a semantic role and accessible name.

**Metadata,** for example: `{"abi":"applet:1","libraries":{"@concept/applet":"1"},"queries":{"summary":"$.summary"},"commands":{"setPosition":{"inputSchema":{"type":"object","properties":{"fen":{"type":"string"}},"required":["fen"],"additionalProperties":false}}}}`. Every command declares its input schema.

**Running.** Opening mounts the applet and pins its revision. Find its commands with `read {resource:'applet', input:{surface, selection:{command}}}` and queue one with `material {kind:'applet', op:'command', command, input:{surface, arguments}}`; its result arrives on a later turn.
