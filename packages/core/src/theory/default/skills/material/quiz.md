# quiz

Kind: `quizzes`. A Problem poses one graded task and a Set sequences Problems. Each Problem separates `answer` (how the learner responds: a choice, short or long text, or work in an applet or roleplay) from `grader` (how it's judged); choose both for the capability being shown. A choice shows recognition, so production is checked by producing; competing options are alike in length and form, and each wrong one may carry the `error` it reveals.

Put separate questions in a Set, one short Problem per item. State `feedback: "each"` for practice with feedback on each answer, or `"end"` for prior-capability, retention and milestone checks whose results should wait until the run ends; this is independent of the `next` strategy and `checks.help`. Reserve `checks`-graded text Problems for one integrated response showing several capabilities (an explanation, essay, project). A fast classifier picks `shown`, `absent` or a named `mistaken` version per check from the learner's text, so describe what a response visibly does. `pumps` together name every check, asking the learner to take each up without giving it away.

`help` sets how far the Problem teaches. `pump` only measures: use it for prior-capability, retention and milestone checks. `hint` shows a mistaken check's hint; `correct` adds the correction if the mistake persists after it. One response counts once per Node however many checks touch it; where help touches a check, that Node is recorded unaided as its checks stood before help and aided as they ended.

Add with `node` or `about`. A prepared prompt clip goes in top-level `promptAudio` (omit on edit to keep; null removes), never in the body.

For type "problem": JSON text in a string, not Markdown; audio is separate: supply top-level promptAudio or Material metadata "audio:prompt", never inside this body. Strict object shape: common required fields {"about":["node-id"],"prompt":"..."}, optional "presentation"; "answer" is {"kind":"choice","options":[{"id":"...","label":"...","correct":true|false,"error":"optional"}]} (at least two options, exactly one correct, unique ids), {"kind":"short"}, {"kind":"text"}, {"kind":"roleplay","material":{"id":"roleplay-id","revision":{"identity":"patch-id","digest":"sha256:..."}}}, or {"kind":"applet","material":{"id":"applet-id","revision":{"identity":"patch-id","digest":"sha256:..."}},"setup":[{"command":"declared command","input":{}}],"read":"declared query"} (setup optional; the exact Notebook revision contains the applet); "grader" is {"by":"mechanical","accepted":["..."]} for short answers (choice uses its option keys), {"by":"tutor"|"learner","rubric":"optional"} for text, applet or roleplay, or {"by":"checks","help":"pump"|"hint"|"correct","checks":[{"id":"...","about":["node-id"],"ask":"question about the response","shown":"what demonstrating it looks like","absent":"what not taking it up looks like","mistaken":{"short-name":"a known wrong version"},"hint":"optional","corrections":{"short-name":"optional, why wrong and the fix"}}],"pumps":[{"text":"asks the learner to take something up, never giving it away","checks":["check-id"]}]} for text, applet or roleplay answers (unique ids; check abouts together are exactly the Problem about; pumps cover every check). Text checks are classified live as the learner writes; applet checks are judged only at submission, using the declared query value serialized as JSON (one match: its value; multiple: an array). Roleplay submission freezes its server-owned, speaker-labelled transcript: judge only learner speech; role speech establishes what was asked, never satisfies a check. Roleplay help above pump is revealed only after submission. Applet setup uses its own declared commands and input schemas, once per attempt; save state before returning from a setup command. Invalid answer/grader pairs are rejected. About must match the Material about Nodes. For type "set": JSON text in a string, not Markdown; strict object shape: {"title":"A concise name for this set","feedback":"each"|"end","problems":["problem-id",...],"next":{"kind":"sequence"}}; "next" may instead be {"kind":"shuffle","seed":"..."|1}, {"kind":"until","correct":1}, {"kind":"prerequisites"}, or {"kind":"custom","js":"...","grades":true}. feedback is required: "each" shows each grade to learner and tutor as it arrives; "end" holds results until the run ends. sequence and shuffle never wait for grading; until and prerequisites wait; custom waits only with grades:true and otherwise receives history without assessments. Problem ids must be distinct; until.correct must be a positive integer. prerequisites requires each Problem to be about exactly one Node in the checkpoint graph; it adaptively assesses prerequisites of the covered Nodes and may skip Problems.
