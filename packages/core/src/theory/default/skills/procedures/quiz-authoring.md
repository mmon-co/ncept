Read `items(node)` for the Quiz Problems already about the Node before making a new one. A Problem separates `answer` from `grader`; the answer says how the learner responds, the grader how it is judged. Use a choice or short answer with the mechanical grader, or text or an applet with a tutor, learner, or checks grader. An applet answer references the saved applet Material by id and exact Notebook revision; optional setup calls its declared commands, and read names its declared JSONPath query. It stays usable standalone. The Quiz judges the saved query value only at submission, not during play; applet code must save state before a setup command returns. Keep these independent: the Playground decides how the answer is presented. Match the capability statement, not a taxonomy of formats.

Choose a task that a real learner could fail. Use competing wrong answers where keyed choice fits, alike in length and form so formatting gives nothing away; optionally give each option an `error` string that preserves the actual mistake wording in the response. No fixed error taxonomy is required. “I don’t know” records its own outcome, weighed like failure for mastery; closing without answering records nothing. In a text Problem with checks, setting a pump aside with “I can't say” records not knowing. Decide unaided conditions before posing; choice on a production capability is aided even when mechanically correct.

Where one rich task can show several capabilities at once (an explanation, a short essay, a small project), prefer one text Problem graded by checks to several narrow ones. Write `checks`, each about the Node it evidences: `ask` (a question about the response), `shown`, `absent`, and `mistaken` naming the likely wrong versions (the rule without the reason, a keyword, a common error). A fast classifier picks one of these per check from the learner's text, so describe what a response visibly does. Write `pumps` that together name every check: each asks the learner to take something up without giving it away, and all show at once, so the learner can see when they've done their best.

`help` sets how far the material teaches. At `pump` it only measures: the learner sees each pump as taken up or not, never right or wrong. At `hint` a mistaken check's pump shows ✗ and its `hint`, and at `correct` the `corrections` for that named mistake appear only if it persists in a revised answer after the hint. A check help touches is recorded unaided as it stood then and aided as it ended, so teach freely without losing the measurement. Use `pump` for prior-capability and retention checks, `hint` or `correct` for a lesson phase you expect the learner to finish fully right.

Pose through the Quiz Playground's **open** with an explicit Problem list, or as a conversational check. The Playground emits the outcome after assessment; evaluate free work with `record_demonstration`. Do not double-record. Adding a Problem retains a Session Material; it is not an evidence write or publication.
