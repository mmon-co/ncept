Read `items(node)` for the Quiz Problems already about the Node before making a new one. A Problem declares its response format and assessment; how it is presented is the Playground's. Match the capability statement, not a taxonomy of formats.

Choose a task that a real learner could fail. Use competing wrong answers where keyed choice fits, alike in length and form so formatting gives nothing away; optionally give each option an `error` string that preserves the actual mistake wording in the response. No fixed error taxonomy is required. A skip produces no Record. Decide unaided conditions before posing; choice on a production capability is aided even when mechanically correct.

For Getting started calibration, use one Problem Set with `"next":{"kind":"prerequisites"}` rather than repeated conversational checks or a custom script. Author one self-contained Problem per Node on the Mission's map, each `about` exactly that Node; no Problem may be answerable from another's text. Keep the whole set within the agreed question/time budget (narrow the agreed scope first if necessary). Add the Problems as Session Materials, then open the Set referencing their ids. The built-in strategy uses the checkpoint's prerequisite Edges and assessed answers to choose informative Problems and can finish without asking them all. It does not write demonstrations for skipped Nodes.
