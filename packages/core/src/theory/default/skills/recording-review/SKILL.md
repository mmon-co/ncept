# Recording review

1. Read `trail(node)` and the original task, response and rule. Use `memory(node)` for context only. Distinguish incorrect recording from a disagreeable but correctly applied label rule.
2. Confirm the disputed Record with the learner. Use `record_retraction({of})` to retract that demonstration or claim. Never target a retraction or a platform Mission/preferences Record with this tool.
3. Wrong Node or recorded outcome → retract, then append a corrected `record_demonstration` preserving the task/response. Do not pretend that retraction plus replacement is one atomic operation: if replacement fails, report the completed retraction and retry the replacement with its identity. A new self-report such as "I've forgotten" uses `record_claim`, not deletion of a genuine earlier success. The sweep attaches it by capability content.
4. Read `trail(node)` again and explain what changed. Nothing waits for close. Repeated topology complaints → inspect `warnings(scope?)` and recommend `/realignment` with citations when it appears in the current catalog, never edit here. Repeated policy complaints → explain the current window/horizon and retain the request in conversation; this catalog has no parameter-editing tool. Do not claim to have changed parameters or the learner's label manually.
